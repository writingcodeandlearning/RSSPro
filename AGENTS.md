# AGENTS.md

## Project

RSSPro is a native Android RSS/Atom reader written in plain Java. There is no Gradle, AndroidX, Maven, or third-party dependency. The UI is in Spanish and built programmatically. `README.md` documents features and filter semantics; `INSTALACIONES.md` documents the vendored toolchain.

## Commands

- `./test.sh` — compile and run all 108 JVM tests. No device/emulator needed.
- `./build.sh` — compile resources/Java, D8 to `classes.dex`, package, zipalign, sign, and verify. Produces `dist/RSSPro.apk`.
- There is no lint, formatter, typecheck, or CI. The two scripts are the executable source of truth.
- No `adb` or emulator is available, so the app cannot be run from this environment; `build.sh` and `test.sh` are the only verification.

There is no single-test selector: `test/test/TestRunner.java` calls every test from `main`. To focus, run `./test.sh` and inspect its output, or compile selected classes with `tools/jdk/bin/javac` and invoke `TestRunner` manually.

## Critical constraints

- `tools/`, `build/`, `dist/`, and `signing/` are gitignored but are required at runtime. Do not delete them. The vendored binaries target aarch64 Linux.
- `signing/rsspro.keystore` and `signing/keystore.properties` must be preserved. Android updates require the same signing key; `build.sh` creates new ones only when missing.
- Do not edit `build/gen/`; it is generated by AAPT2.
- Java compiles with `-source 8 -target 8` against `tools/android-platform/android-13/android.jar`. Follow the existing Java 8 + anonymous-class style; do not introduce AndroidX or new dependencies.
- `test.sh` hardcodes the source files it compiles. Any new class used by tests must be added there, and new tests registered in `TestRunner.main`. Tested classes must stay free of `android.*` imports because `test.sh` does not put `android.jar` on the test classpath.

## Architecture notes

- `MainActivity.java` is a ~2,800-line monolith that constructs the Articles/Feeds/Filters tabs and dialogs in Java. There are no layout XML files.
- `RssProApp` schedules background maintenance; `notify.RefreshJobService` and `notify.BootReceiver` handle sync scheduling.
- `store.Store` persists feeds/rules/read state in SharedPreferences `rsspro_prefs` and cached articles in `articles.json`. Wrap sync/cache mutations in `Store.SYNC_LOCK`.
- `core/` holds pure-Java logic (search, filters, simulator, retention, filter backup). Put testable logic there rather than in activities.
- `net/` handles fetching, feed parsing, and full-article extraction. `FeedParser` intentionally disallows DOCTYPE and external entities; preserve those XXE protections.

## Conventions

- User-facing text, documentation, and commit messages are Spanish.
- UI strings are hardcoded in Java; `res/values/strings.xml` contains only `app_name`.
- Version changes go in `AndroidManifest.xml` (`versionCode`/`versionName`). README/INSTALACIONES release notes may lag the manifest.
